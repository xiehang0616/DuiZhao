# 麋鹿-对照-模型测评

**DuiZhao** · 面向 AI 产品经理的多模型对比与人工测评工作台。

将同一道业务问题交给多个模型，比较回答、图片、代码或视频，再通过固定用例、验收条件和评分规则形成可复查的选型依据。

本文按 2026-09-24 的源码整理。真实调用需要自行配置兼容服务与 API Key；演示内容、费用估算与正式测评记录应分别理解。

## 功能介绍

| 功能 | 当前能力 |
| --- | --- |
| 多模型对比 | 同一问题、共同系统提示词；文本、图片理解和代码通常选择 2–9 个模型，图片与视频生成至少 1 个 |
| 五种内容类型 | 文本、图片生成、图片理解、代码、视频；结果保留在当前话题 |
| 模型配置 | 服务商预设、独立连接、能力筛选、连接诊断；新增千问 AI 平台预设 |
| 独立输出 | 各模型独立流式返回；支持停止、错误提示、真实耗时和上游返回的 Token 用量 |
| 多模态 | 参考图生图、首帧生视频、图片理解；生成媒体可落盘并通过后端地址访问 |
| 费用估算 | 按内置价格表估算人民币费用；文本按 Token、图片按张、视频按时长与规格 |
| 我的题库 | 保存系统提示词、案例、验收条件、严重错误清单和评分标准 |
| 人工测评 | 固定模型与用例快照、独立重复、失败重试、证据、加权评分和汇总报告 |
| 导出 | 普通对比：Excel / CSV / Markdown；测评任务：汇总 Excel / 明细 Excel / Markdown / JSON |
| 保存 | 浏览器本地副本、后端 SQLite；可配置媒体目录与数据库快照持久化目录 |
| C2C | Single / T2T / C2C 三种方式的前端交互演示，尚未接入真实缓存推理后台 |

图片规格、视频分辨率和时长能否使用，取决于模型与服务商协议。预设代表连接模板，不代表所有模型已逐一实测。

## 使用流程

```mermaid
flowchart LR
    A[配置模型与连接] --> B[验证连通性]
    B --> C[选择内容类型与模型]
    C --> D[输入问题与附件]
    D --> E[查看结果并评价]
    E --> F[固定用例开展人工测评]
    F --> G[导出报告]
```

1. **配置模型**：在“模型配置”添加预设或自定义模型，核对服务地址、模型 ID、能力与 API Key。独立连接可单独设置密钥；已有服务商级密钥可按配置继承，不能默认认为所有新连接会自动共享。
2. **验证连接**：文本类连接测试会发起一次最小真实调用，可能消耗额度。图片与视频测试会提示跳过，需要在对应模式实际生成验证。
3. **发起对比**：选择内容类型与模型，输入共同问题及系统提示词。图片理解需要上传图片；图生视频使用首张参考图。
4. **阅读结果**：比较各卡片的输出、耗时和用量，填写“更好 / 较差”、1–5 分与备注。缺少配置时可能得到标注来源的演示结果，请检查来源。
5. **正式测评**：在题库定义验收与评分标准，建立测评任务，人工录入实际结果与证据。普通对话评分与任务加权分是两套口径。
6. **导出留存**：普通对比导出适合回看本轮或话题；测评任务导出适合复查测试条件、评分和重试过程。媒体引用不等于媒体文件备份。

详细步骤见 [使用文档](使用文档.md)。

## 安装方法

需要 Node.js 22+；后端建议 Python 3.11。仓库若为私有，需要先获得访问权限。

```bash
git clone https://github.com/xiehang0616/DuiZhao.git
cd DuiZhao
npm ci
npm run dev
```

打开 `http://127.0.0.1:8768/arena.html`。上述命令启动前端开发服务；真实调用还需要后端。

另开终端，从仓库目录运行：

```bash
cd backend
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# 仅首次创建环境文件时复制，已有 .env 请保留
cp -n .env.example .env
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

密钥在本机环境配置或网页连接设置中填写，不写进源码。`http://127.0.0.1:8000/health` 只检查应用存活，不代表模型已连通。

前端修改后自动构建，刷新页面查看；退出终端服务使用 `Ctrl+C`。同域预览、端口调整和持久化配置见 [开发说明](docs/开发说明.md)。

## 评分规则

先判断业务验收，再计算质量分。运行失败、验收项不通过或出现严重错误时，验收判定不通过；质量分不能覆盖验收结论。

| 模块 | 默认维度与权重 |
| --- | --- |
| 文本 | 事实正确性 30%、完整性 20%、指令遵循 20%、可用性 20%、表达质量 10% |
| 图片 | 内容与指令 30%、结构与画质 25%、构图与风格 20%、任务专项 25% |
| 视频 | 内容与动作 25%、时序一致性 25%、运动合理性 20%、画面质量 15%、任务专项 15% |
| 代码 | 功能正确性 40%、边界与回归 25%、工程质量 15%、任务专项 20% |

每个适用维度人工打 1–5 分，权重为正数且总和为 100%。

```text
质量分 = 100 × Σ[权重 × (维度分数 − 1) / 4] ÷ Σ适用权重
```

- 1 分对应 0，3 分对应 50，5 分对应 100；结果保留一位小数。
- 未测不按 0 分计算；不适用要说明原因，并从分母排除。
- 同一独立重复以最新尝试为最终结果，失败重试不增加独立重复次数。
- 模型总分先按用例求均分，再对用例等权平均；评分不完整或适用维度不一致时不强行生成总分。
- 示例：文本维度依次为 4、5、4、3、4，质量分为 **75.0**。

完整验收、首次通过率、合格成本和导出口径见 [测评任务与报告](docs/测评任务与报告.md)。

## 费用与数据边界

普通对比显示的人民币金额是**源码内置价格表的估算值**，不是服务商实时账单。未收录模型显示“未计价”；图片与视频规格使用估算倍率。当前已计价文本模型缺少 usage 时可能显示 ¥0，不能据此判断免费。正式成本比较应核对实际用量和账单。

生成媒体支持后端落盘；配置 `PERSIST_DIR` 后可备份和恢复 SQLite 快照。持久化依赖实际挂载、写入权限和备份成功，不能承诺所有实例故障或多实例场景下数据绝不丢失。

当前尚无完整账号鉴权与用户隔离；数据库包含连接密钥，应按敏感文件管理。不要将本地开发服务直接开放给所有人。C2C 真实推理、测评任务自动批跑和自动裁判仍未实现。
