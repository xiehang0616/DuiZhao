# DuiZhao 安装与运行

本文提供本地开发和本地同域运行两种方式。两种方式使用同一套源码，真实模型调用都由 Python 后端处理。

## 环境准备

- Git：获取项目。
- Node.js 22 或更新版本：安装前端依赖并构建页面。
- Python 3.11：建议使用独立虚拟环境运行后端。
- 自行准备兼容模型服务的地址、模型 ID 和 API Key；只浏览页面时不需要真实密钥。

```bash
git clone https://github.com/xiehang0616/DuiZhao.git
cd DuiZhao
node --version
npm ci
```

项目使用 `package-lock.json` 固定前端依赖，安装时使用 `npm ci`。后端依赖由 `backend/requirements.txt` 声明。

## 方案一：前后端分别运行

适合修改源码或日常本地使用。需要两个终端。

### 终端一：前端

在项目根目录运行：

```bash
npm run dev
```

浏览器打开 `http://127.0.0.1:8768/arena.html`。开发脚本会监听源码并重新构建，修改后手动刷新页面。

### 终端二：后端

在项目根目录运行。macOS / Linux：

```bash
cd backend
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Windows PowerShell：

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Windows 命令直接调用虚拟环境中的 Python，无需更改 PowerShell 执行策略。本轮未在 Windows 实机验证。

首次安装才需要创建虚拟环境和安装依赖；下次运行时，激活已有环境或直接调用其中的 Python 即可。

访问 `http://127.0.0.1:8000/health`，正常应返回 `{"status":"ok"}`。这只表示后端启动成功，模型是否可调用还要单独测试。

## 方案二：后端同时提供网页

适合使用构建后的页面。先按方案一安装后端依赖，然后在项目根目录执行：

```bash
npm run build
python3.11 -c "from pathlib import Path; import shutil; p=Path('backend/static'); p.mkdir(parents=True, exist_ok=True); [shutil.copy2(n, p/n) for n in ('arena.html', 'index.html', 'loading-demo.html')]"
```

Windows 将上面的 `python3.11` 替换为 `py -3.11`。接着按方案一启动后端，打开 `http://127.0.0.1:8000/arena.html`。这种方式不需要另起前端 8768 服务。

每次修改源码后，需要重新构建并复制 HTML。直接启动后端但未准备 `backend/static/` 时，健康检查可能正常，网页仍无法打开。

## 配置模型与密钥

1. 打开“模型配置”，添加预设或自定义模型。
2. 核对服务地址、模型 ID 与能力，再填写 API Key 并保存。
3. 对文本类模型执行连接测试；图片和视频模型在对应模式进行一次实际生成验证。
4. 确认连接可用后，按照 [使用流程](../使用文档.md) 发起对比。

也可将 `backend/.env.example` 复制为本机 `backend/.env`，填写服务商级配置。已有 `.env` 时不要覆盖。示例文件中的密钥字段必须保持为空，实际 `.env` 不提交到 GitHub。

网页保存的密钥位于后端私有配置，数据库也需要保密；请勿把数据库、日志或个人连接截图上传到公开仓库。

## 数据与持久化

| 内容 | 默认位置或配置 |
| --- | --- |
| 浏览器数据 | 当前浏览器来源下的 localStorage |
| 后端数据库 | `backend/data/duizhao.db` |
| 生成图片和视频 | `backend/data/media` |
| 自定义数据库 | `DATABASE_URL` |
| 自定义媒体目录 | `MEDIA_DIR` |
| 可选快照目录 | `PERSIST_DIR` |

更换端口、浏览器或主机可能使用不同的浏览器存储。导出报告便于留存，但当前没有完整 JSON 导入恢复流程，媒体引用也不等于备份媒体文件。

`PERSIST_DIR` 需要真实可写的持久化目录或存储挂载。当前快照失败不会自动告警，也没有多实例写入协调；部署前应实际验证恢复流程。当前服务没有完整账号鉴权与用户隔离，本指南的监听地址仅限本机。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| `npm ci` 失败 | 核对 Node.js 版本、网络和锁文件；不要复制别人的 node_modules |
| Python 或依赖找不到 | 确认 Python 3.11 已安装，且使用虚拟环境中的 Python |
| 页面正常但模型列表或连接读取失败 | 检查 8000 后端服务及 `/health` |
| 地址或模型不存在 | 核对兼容 API 的服务地址与模型 ID，不要把网页聊天地址当 API 地址 |
| 认证失败 | 核对 Key、服务商账户权限、额度及所选连接；不要在问题反馈中粘贴密钥 |
| 端口被占用 | 关闭已有服务，或同时调整端口和相关前后端配置 |
| 图片或视频不可调用 | 检查模型能力与协议支持，并在对应模式验证 |
| 显示演示内容或费用为零 | 检查数据来源、Token 用量与计价支持，不能据此认定真实调用成功或免费 |

前端默认端口是 8768，后端 CORS 也按该端口配置。只更改前端端口可能导致跨域错误；后端端口调整还需要同步修改前端 API 地址。详细配置见 [开发说明](开发说明.md)。

## 停止与检查

服务所在终端按 `Ctrl+C` 停止。可在项目根目录运行 `npm test` 和 `npm run build`；在后端目录、虚拟环境中运行 `python -m pytest tests -q`。

模型连接测试和真实生成可能产生服务商费用；安装、构建及现有单元测试不需要填写真实密钥。
