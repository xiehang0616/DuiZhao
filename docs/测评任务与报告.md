# 测评任务与报告

本说明按 2026-09-24 的 `src/evaluations.mjs` 与当前界面整理，适用于人工测评任务。普通对话中的整体 1–5 分不等于任务内的多维加权质量分。

## 1. 建立任务

在“我的题库”中，为每个用例填写模块、任务类型、系统提示词、问题和参考材料，并明确验收条件、严重错误及评分标准。

新建测评任务时选择同一模块的用例和 2–9 个不同模型，填写版本、共同测试条件和评价人。任务采用统一评分模板，初始值来自首次选中的用例，创建前可以调整。

任务创建后保存模型、用例、提示词、验收项、评分维度、权重与指引的快照。修改题库或模型配置不会回写已建立的任务；测试条件改变时应新建任务。

## 2. 录入结果与证据

每个用例点击“新增独立测评”，为各模型新增一次记录。模型运行需要在实际调用工具中完成，当前测评任务不会自动调用模型。

记录包括原始输出或媒体引用、运行状态、实际运行时间、逐项验收、维度分数、证据与定位、评价人、采纳情况及返工耗时。可以先保存尚未完成的评价。

运行状态为“已完成”时必须提供原始输出或媒体引用；标记失败需要填写失败原因。耗时、费用与 Token 均可留空，但不能用估算值代替未采集值。

从普通对话创建的任务副本当前统一标为 `demo` 来源，并清空性能指标。即使原对话来自真实 API，也不自动转换为正式实测记录；正式记录请通过新增独立测评人工录入。

## 3. 业务验收

| 状态 | 判定条件 |
| --- | --- |
| 通过 | 运行成功，所有验收项通过，所有严重错误均明确标记为未出现 |
| 不通过 | 运行失败，或至少一项验收不通过，或出现严重错误 |
| 待评价 | 尚未完成运行，或必须的验收/严重错误检查尚未填完 |

验收与质量分独立。成功生成但违反业务规则的回答，可以有完整质量评分，同时判定为不通过。

## 4. 默认评分模板

| 模块 | 维度 | 权重 |
| --- | --- | --- |
| 文本 | 事实正确性 / 完整性 / 指令遵循 / 可用性 / 表达质量 | 30 / 20 / 20 / 20 / 10 |
| 图片 | 内容与指令 / 结构与画质 / 构图与风格 / 任务专项 | 30 / 25 / 20 / 25 |
| 视频 | 内容与动作 / 时序一致性 / 运动合理性 / 画面质量 / 任务专项 | 25 / 25 / 20 / 15 / 15 |
| 代码 | 功能正确性 / 边界与回归 / 工程质量 / 任务专项 | 40 / 25 / 15 / 20 |

所有权重均以百分比计，单项大于 0，总和为 100%。维度名称、权重和指引可在创建任务前修改。

“任务专项”需要结合具体任务定义，例如图片文字准确性、视频参考一致性、代码测试质量。评价图片理解或代码功能时，需要相应参考答案、检查步骤或运行证据。

为了保持不同评价人的标准一致，可采用以下起始标尺，再按业务细化。它是建议的人工评判方式，不是自动打分规则。

| 分值 | 建议含义 |
| --- | --- |
| 1 | 该维度明显不满足要求，存在关键问题 |
| 2 | 部分满足，但需要较多修改 |
| 3 | 基本满足，需要一定修改 |
| 4 | 大部分满足，仅需少量修改 |
| 5 | 充分满足该维度的预定要求 |

## 5. 单条质量分

设第 i 个适用维度分数为 sᵢ，权重为 wᵢ：

```text
质量分 = 100 × Σ[wᵢ × (sᵢ − 1) / 4] ÷ Σwᵢ
```

映射为 1 分→0，2 分→25，3 分→50，4 分→75，5 分→100，结果四舍五入到一位小数。

只有运行成功且所有适用维度完成评分时，才产生本条质量分。

- **未测**：阻止本条质量分生成，不按 0 分计算。
- **不适用**：排除该维度，按剩余权重归一化，需要在评价备注中说明原因。
- **全部不适用**：不产生质量分。
- **运行失败**：不产生质量分，并计入验收失败记录。

文本默认模板下，分数 4、5、4、3、4 对应：

```text
100 × (30×0.75 + 20×1 + 20×0.75 + 20×0.5 + 10×0.75) ÷ 100
= 75.0
```

如果该回答编造了关键业务规则，应根据任务定义标记验收失败；75.0 的质量分不会将其改为通过。

## 6. 独立重复与失败重试

“新增独立测评”增加独立重复次数。“失败重试”属于原重复中的下一次尝试，不增加独立重复次数。

只有运行失败或验收不通过的正式记录可以重试。产生重试后，旧尝试保留为只读证据；最终结果采用该次独立重复的最新尝试。

演示记录不执行重试，需要新增独立测评录入真实结果。

## 7. 汇总与模型总分

逐用例统计按“模型 × 用例 × 数据来源”隔离，正式记录和演示记录分开。

1. 每次独立重复只取最新尝试参与最终质量汇总。
2. 同一用例先计算有效质量分的平均值；适用维度集合不一致时不合并均分。
3. 模型总分对各用例均分进行等权平均，避免某个用例测试次数更多而获得额外权重。
4. 只有全部用例覆盖、最新尝试的必需评分完整且适用维度集合一致时，才显示模型总分。

局部用例均分可能只覆盖已完成评分的记录，阅读时应同时查看评分样本数。模型总分不是合格率，也不是跨任务通用排名。

### 首次通过率

```text
首次通过率 = 验收通过的首次尝试数 ÷ 已完成验收的首次尝试数
```

尚未验收的首次尝试不进入分母，应同时查看未验收情况。

例如做了三次独立测试：第一次失败后重试通过，第二次首次通过，第三次尚未验收。首次通过为 **1/2**；最终通过的独立测试为 **2 次**，仍有 **1 次**待验收。重试不会把首次通过改成 2/2。

### 耗时与费用

- 耗时只平均非待运行记录中已人工采集的有效样本，并显示样本数；旧重试也属于耗时样本。
- 费用统一为人民币 CNY，记录实际测量或账单来源；Token 数为非负整数。
- 已结束尝试的费用全部有值时才计算总费用，旧重试费用也计入。
- 最终验收完成、有合格结果且费用完整时，合格成本为总费用除以最终合格的独立结果数。
- 没有合格结果显示“无合格成果”，费用缺失显示未采集；演示记录不统计真实性能与费用。

## 8. 导出与保存

| 文件 | 内容 |
| --- | --- |
| 汇总 Excel（.xlsx） | 模型总览、逐用例汇总、样本数和统计分母 |
| 明细 Excel（.xlsx） | 每次尝试一行，包含模型版本、提示词、输出、验收、分数、证据、费用与重试关系 |
| Markdown | 完整测评报告、测试条件、结果、证据及人工适用性结论 |
| JSON | 完整任务快照、所有尝试与评价，用于留存和后续迁移 |

界面当前输出 Excel；内部仍使用 `detailCSV`、`summaryCSV` 组织表格，再转换为工作簿。

任务保存在浏览器 `arena-evaluation-tasks-v1`，并尝试同步至后端 SQLite。当前同步没有完整冲突合并或失败重试保障，不能把本地保存成功等同于远端备份成功。

媒体仅保留文件名、说明或引用链接，不打包远程图片/视频；导出 JSON 也不表示已有导入恢复功能。

## 9. 实现与验证依据

- `src/evaluations.mjs`：标准快照、验收、计分、重试、汇总和报告数据。
- `src/evaluations-ui.jsx`：任务创建、结果录入与导出入口。
- `src/excel.mjs`：Excel 文件生成。
- `src/arena.jsx`：存储同步和对话建任务。
- `tests/evaluations.test.mjs`：已有评分、缺失值、重试及导出回归测试。

本说明按当前源码核对，不新增模型测评成绩。2026-09-24 最近一次整体验证为 46 项前端测试和 27 项后端测试通过；本次文档更新未重新执行模型调用或浏览器验收。
